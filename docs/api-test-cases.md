# API Test Cases — Booking REST API

Тест-кейсы для REST API системы бронирования. Реализованы как автотесты в Postman-коллекции
`postman/booking-api.postman_collection.json` и прогоняются в CI через Newman.

Условные обозначения: **P** — позитивный сценарий, **N** — негативный.

| ID | Тип | Запрос | Предусловие | Шаги | Ожидаемый результат |
|----|-----|--------|-------------|------|---------------------|
| API-SMK-01 | P | `GET /posts` | API доступно | Запросить список заявок | 200 OK; тело — непустой массив; `Content-Type: application/json`; время ответа < 3000 мс |
| API-POS-01 | P | `GET /posts/1` | Заявка id=1 существует | Запросить карточку заявки | 200 OK; тело валидно по JSON Schema (`userId`, `id`, `title`, `body`); `id == 1` |
| API-POS-02 | P | `POST /posts` | — | Создать заявку с валидным телом | 201 Created; сервер вернул `id`; переданные `title` и `userId` сохранены |
| API-POS-03 | P | `PUT /posts/1` | Заявка id=1 существует | Обновить заявку | 200 OK; изменённые поля отражены в ответе |
| API-POS-04 | P | `DELETE /posts/1` | Заявка id=1 существует | Отменить (удалить) заявку | 200 OK |
| API-POS-05 | P | `GET /posts?userId=1` | У клиента 1 есть заявки | Отфильтровать по клиенту | 200 OK; все элементы имеют `userId == 1` |
| API-NEG-01 | N | `GET /posts/999999` | Заявки нет | Запросить несуществующую заявку | 404 Not Found; тело пустое |
| API-NEG-02 | N | `GET /unknown-route-qa` | — | Запросить неизвестный маршрут | 404 Not Found |
| API-IDM-01 | P | `GET /posts/2` (×N) | Заявка id=2 существует | Повторно запросить ресурс | Ответ детерминирован: 200 OK, `id == 2` |

## Что проверяется на уровне ответа

- **HTTP-статусы:** 200 / 201 / 404 для соответствующих операций.
- **Контракт (JSON Schema):** структура и типы полей карточки заявки.
- **Бизнес-данные:** сохранение и обновление переданных полей, корректность фильтрации.
- **Нефункциональное:** время ответа (SLA-порог), корректный `Content-Type`.
- **Устойчивость:** обработка несуществующих ресурсов и маршрутов, идемпотентность чтения.

## Бэкенд для демонстрации

В качестве стабильного публичного API используется [JSONPlaceholder](https://jsonplaceholder.typicode.com),
который имитирует CRUD-ресурсы: заявки/брони как `posts`, клиентов как `users`.
Это позволяет прогонять набор в CI без приватной инфраструктуры, сохраняя реалистичную структуру проверок.
